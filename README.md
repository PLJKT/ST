# ST v5 — 一个账本，两个门面

把原 `PLJKT/ST`（加密静态台账分析站）和 `stock-snapshot`（FastAPI + yfinance 实时行情站）合并成**一套系统**：

- **门面一 · 组合**：三账户（富途牛牛 / POEMS SG / POEMS ID）、多市场（美股 / 港股 / 印尼股，A 股参考）的持仓与权益监控，净值曲线、对账中心、标的盈亏、历史台账。
- **门面二 · 选股**：按代码或中文名搜票、看单票基本面与 K 线、按条件筛新股、观察池、交易前模拟。

原 ST 的台账数据（解自 `site/vault.json` 的 analytics.json，revision 4）已整体灌入 SQLite，成为新系统的账本层；实时行情与汇率来自 Yahoo Finance。

**在线浏览（静态快照，只读）**：<https://pljkt.github.io/ST/> — 由 `tools/export_static.py` 把 `/api/*` 全量导出成 JSON 推到 `gh-pages` 分支。快照里可看真实台账、分市场盘面、逐仓止盈止损、对冲与回本；新增/修改/删除等写操作仍需在本机服务上做。


## 数据口径（这六条决定了所有数字）

1. **空头市值记为负**：卖空是负债，不当作资产。持仓表、市场分布、合并权益都按 `-(qty × price)` 计。
2. **账户状态决定权益**：只有 `accounts.status='closed'` 的账户把 `positions_usd / cash_usd / equity_usd` 归零、只留历史已实现；`active` 账户一律按"持仓市值（实时价 / 人工价）+ 现金"计权益。POEMS SG 在 2026-11 已由 `closed` 恢复 `active`（此前被强制归零是错的）。
3. **无代码台账行不进权益**：没有证券代码的历史台账行统一进"历史台账"区留档，不参与任何合计；小数数量/无成本的异常行标 `台账异常行`。
4. **权重按总敞口**：分母是持仓绝对值之和，空头不会把某只票的权重顶到 100% 以上。
5. **实时为主口径、台账为次级**：KPI 区只放实时数字（权益 / 持仓市值 / 现金 / 浮动 / 净盈亏 / 杠杆）；ST 定稿（`$16,769.32`，2026-09-24）降为下方一条"台账定稿"横条，显示实时差额，差额只来自此后行情变动，不是数据错误。
6. **数据三态，不删原始行**：`positions` / `closed_trades` / `trade_events` 三表都有 `quality`（`ok` / `flag` / `reject`）与 `quality_note`。`reject` 不进入任何合计、筛选、时间线与台账视图；`flag` 保留但单独说明。原始台账是唯一可信源，所以体检只打标记，不改数、不删行，随时可复核。

## 定价与行情更新（2026-11 新增）

**取价优先级（四层）**：人工定价 > 实时报价 > 最近收盘价 > 台账价。每一行都带来源标签，看到数字就知道它是怎么来的。

| 来源 | 触发条件 | 页面标签 |
|---|---|---|
| 人工定价 | `price_overrides` 表里有这只票 | `手动价` |
| 实时报价 | Yahoo 返回有效价（缓存 5 分钟） | `◐ 5m` |
| 最近收盘价 | 实时价缺失（休市 / 停牌 / 数据源失败），用 `daily_closes` | `收盘价` |
| 台账价 | 三层都没有，退回开仓时的台账价 | `台账价` |

**① 人工改价**：持仓表每行的「价」按钮打开弹窗，填现价 + 原因（券商延迟 / 停牌 / 修正错价）。保存后这只票的市值、浮盈、权重、组合权益、逐仓止盈止损、对冲与回本全部按新价重算；「清除手动价」恢复自动取价。人工价与原始台账分开存（`price_overrides`），不改持仓行的成本与数量。

**② 强制刷新**：顶部「刷新行情」现在先 `POST /api/prices/refresh`，跳过 5 分钟缓存逐只重拉，再刷新页面；失败的标的会在返回值里列出。

**③ 收盘价自动落库**：`tools/update_close.py` 拉持仓标的最近日线收盘写进 `daily_closes`（每只一行，带交易日与来源）。挂在 Windows 计划任务里每天收盘后跑一次即可：

```bat
schtasks /create /tn "ST update close" /tr "\"<local>" run --with fastapi --with uvicorn --with yfinance python tools\update_close.py" /sc daily /st 06:30 /f
```

（`/st` 用本机时间；港股 16:00、美股 04:00/05:00 收盘，取早上跑一次已覆盖前一交易日。）

**⑤ 持仓增改删**（`app/edit.py`）

- 新增：生成 `manual:<hex>` id，校验账户 active、市场在账户可交易列表内，拒 SG/CN，数量>0、成本>0（空头也用正数量）。
- 修改：同套校验，改完置 `quality='ok'` + `quality_note='手工修改'`；账户不可改（换账户等于另一笔仓）。
- 删除：硬删（`positions` 一行，不影响历史台账）。
- 现金：`POST /api/cash` 直接写 `cash_balances`（`source=manual`），用于把负数现金补正。
- 语义：**新增持仓立即计入权益与权重，现金不变**（等于建仓金额由保证金/自有资金承担）。要"买入同时扣现金"，先补一笔现金再建仓即可。

**⑥ 交易纪律检查**（`app/discipline.py`，2026-11 新增）

把公开交易纪律固化成常量表（`RULE`），检查的是库里真数字，不是建议：

| 规则 | 阈值 | 口径 |
|---|---|---|
| 2% 法则 | 单笔最大亏损 ≤2% 权益 | 按 10% 止损反推名义仓位：`名义×10% / 权益` |
| 单票集中度 | ≤30%，≥50% 硬失效 | 该标的合计市值 / 总敞口 |
| 总敞口倍数 | ≤2.0x 权益 | 多空绝对值合计 / 权益（风险分母用当前权益，新增不扣现金不稀释） |
| 现金缓冲 | ≥0 | 负现金＝占用保证金 |
| 空头敞口 | ≤10% | 空头绝对值 / 总敞口 |
| 杠杆 ETF 隔夜 | ≤10% | 3x 产品每日重置，只适合日内 |
| 历史赔率 | ≥1.0 | 均盈 / 均亏（来自 389 笔有日期交易） |
| 历史期望值 | >0 | 胜率×均盈 − 败率×均亏 |

- 接口：`GET /api/discipline` 返回组合层 8 条规则的状态（`pass / warn / danger`）与通过数统计；`POST /api/positions/check` 传入 `account/symbol/side/qty/avg_cost[/price][/exclude_id]`，返回这一笔落地后的预检（名义、集中度、总敞口倍数、风险占权益、是否必须二次确认）。
- 弹窗实时预检：代码 / 数量 / 成本填齐后 450ms 触发一次预检，逐条显示「通过 / 超限 / 失效」；有 `danger` 时保存按钮变「确认超限保存」，第一次点击只提示不写入，再点一次才真正落库（`requires_confirm`）。
- 分析页新增「纪律检查」面板：8 条规则的当前值 vs 上限 + 一句解释，右上角「重新检查」手动刷新。

**⑦ 盘面 / 逐仓止盈止损 / 对冲与回本**（`app/risk.py`，2026-11 新增）

三个问题各自给一套可复算的数，不猜方向：

| 模块 | 算法 | 口径 |
|---|---|---|
| 逐仓盈亏比 | `rr = 有利距离 / 不利距离` | 止损/止盈都按日线结构算，不用主观百分比 |
| 止损位 | `min(p−2ATR, 20日低−0.3ATR)`，夹到 `p−3ATR` 以内 | 空头对称：`max(p+2ATR, 20日高+0.3ATR)`，上限 `p+3ATR` |
| 止盈位 | `max(p+3ATR, 20日高+0.1ATR)`，上限 `p+5ATR` | 空头对称 |
| 首达概率 | `不利距离 / (不利+有利)` | 无漂移随机游走先碰止盈的概率，不是预测 |
| 期望 | `胜率×有利 − 败率×不利`，×数量×汇率 | 该标的≥5 笔用其自身胜率，否则用整体胜率（389 笔 65.55%） |
| 盘面 | 每市场 1–4 个指数：价、日涨跌、20/50/200 日均线、距 52 周高、ATR% | 指数一律绕开 `market.resolve`，避免 `^HSI` 被拼成 `^HSI.HK` |
| 对冲 | `敞口 = |市值| × beta × 方向`，按市场汇总后与 SPY / 2800.HK 对齐 | **杠杆 ETF 用产品倍数**（SQQQ −3、TQQQ +3…），其余用近 120 日回归 beta；回归对每日重置产品会算出 −4.8 这类失真值 |
| 可行性 | 需对冲名义 > 当前权益即标 `feasible=false` | 当前美股净敞口约 −$120k ≈ 权益 5.1 倍，结论写"只能减仓" |
| 情景 | 基准 −10% / −20% / +10% 下的未对冲 vs 已对冲盈亏 | 不含汇率与个股特有事件 |
| 回本 | 逐仓 `breakeven = 成本价`，多头需涨 / 空头需跌；组合层按敞口同比例 | 空头口径是 `(现价−成本)/成本`，方向固定为"跌" |

- 接口：`GET /api/risk` → `levels[]`（逐仓）/ `board`（分市场盘面 + notes）/ `hedge`（by_market / scenarios / warning）/ `breakeven`（losers + 组合回本幅度）/ `summary`。
- 性能：首次 ~8 秒（16 个标的 1 年日线，6 线程并行预热），结果进程内缓存 30 分钟；页面首行会提示"计算中"。
- 风控页新增「市场盘面」「逐仓：盈亏比 / 概率 / 止盈止损」「对冲与回本」三块；`#risk` hash 可直达。

## 界面

**组合页**

- 顶部工具条：**账户下拉真正作用于整页**（KPI、持仓、净值、市场分布一起切），**折算下拉**把 USD 口径数字换算成 USD / HKD / SGD / IDR 展示（后端仍用 USD 记账，换算只发生在展示层，持仓行的原币市值旁附折算值）。
- 三张账户卡：权益 / 持仓 / 现金 / 已实现 / 浮动 / 台账留档 / 市场标签 / **数据来源与新鲜度**（绿点＝逐月更新，灰点＝存档台账）。
- KPI 六项：权益、持仓市值（空头为负）、现金、浮动盈亏、净盈亏（已实现＋浮动）、杠杆（持仓/权益）。
- 台账定稿横条：定稿日期、权益、已实现、与实时的差额，附"看台账 →"跳转；切到单账户时提示"台账是三账户合计，本账户视图不比较"。
- 持仓表（13 列）：账户、代码、名称、市场、多空、数量、成本、现价（带来源标签：◐ 5m 实时 / 手动价 / 收盘价 / 台账价）、市值（附记账币）、浮盈、权重（占敞口）、**风险标注**、**操作（价 / 改 / 删）**；数量/成本/现价/市值/浮盈/权重可点表头排序；同一标的跨账户自动加"合并"行；右上角 **＋ 新增持仓** 打开弹窗（账户/代码/名称/方向/数量/成本/开仓日/备注）。
- 净值曲线：POEMS 23 个月度点 + FUTU 期末单点。
- 市场分布：净市值条形（空头为负、红条），随折算币种换算。
- 对账中心：9 项 ST 三方对账（成交↔资金、现金链、双口径、重复成交、数据段缺口、账户-市场越界）。
- 标的盈亏：FUTU 23 个标的的 FIFO 已实现、开多/开空、胜率。
- 历史台账：无代码行留档（剔除行不再显示），异常行有标记。

**分析页**

- 数据体检：三表三态汇总 + 被标记行（默认只列前 10 行、剔除优先，可展开全部）+ "重新体检并应用"。
- 交易时间线：两张阶段卡（账户 / 打法 / 笔数 / 已实现 / 胜率赔率 / 平均持有 / 杠杆 ETF 占比 / 主要标的）+ 月度已实现柱状图。
- 交易偏好画像：8 张 KPI + 5 条结论。
- 纪律检查：8 条规则（2% 法则 / 集中度 / 总敞口 / 现金 / 空头 / 杠杆 ETF / 赔率 / 期望值），状态分「通过 / 超限 / 失效」。
- 下一步动作：5 条带数字的可执行建议。
- 风险清单：9 条分级卡。
- 标的分布：代码 / 笔数 / 已实现 / 胜率 / 类型。

**风控页**

- 市场盘面：四张市场卡（美股 / 港股 / 印尼股 / A 股参考），每张列该市场指数（价、日涨跌、vs200、距 52 周高、ATR%）+ 本市场持仓敞口与浮盈；下方是自动生成的提示（VIX 分档、指数在 200 日均线下方、距 52 周高 ≥15%、单一市场敞口超权益）。
- 逐仓表：13 列，止损位 / 止盈位带距离百分比，盈亏比 / 首达概率 / 历史胜率（不足 5 笔回退整体胜率并注明）/ 期望 / 一句话提示。
- 对冲与回本：净 beta 敞口横幅 + 逐市场对冲表（标的、方向股数、名义、可行性）+ 三情景表（未对冲 / 对冲后 / 差额）+ 浮亏标的回本表。

**选股页**

- 搜索：支持代码（AAPL / 0700.HK / BBCA.JK）与**中文名**（腾讯 / 苹果 / 中亚银行…，本地别名表补齐 Yahoo 不索引中文的缺口）。结果只保留 US/HK/ID/CN 四个市场，多伦多、墨西哥等无关交易所会被过滤。
- 单票：价格、市值、PE、PB、股息率、ROE + 1 年 K 线（日期按交易所本地交易日，不做 UTC 偏移）。
- 交易前模拟：只列出**能交易该市场**的活跃账户；越界账户会被后端拒绝。
- 筛选器：市场多选 + PE/PB/股息率/ROE/市值/价格阈值，缺失字段默认排除，可勾选保留；命中数按实际满足的条件计。
- **导出 CSV**：把当前筛选结果（代码/名称/市场/币种/价格/PE/PB/股息率/ROE/市值/命中条件数）导成带 BOM 的 UTF-8 CSV，Excel 直接打开不乱码；导出沿用上次运行的参数。
- 观察池：只记录想法，不触发下单。

- **POEMS SG 回报率仍是 2020–2022 台账口径**：SG 2026 年只有两张持仓快照、没有成交单据，账户卡里的月/年回报来自 267 行旧台账，界面已标「2020–2022 台账口径（2026 期无成交单据）」，不要当成 2026 年的表现。
- **报价是 Yahoo 快照 + 5 分钟缓存**：不是逐笔 Level-2；交易决策请以券商为准。
- **中文名覆盖有限**：`aliases.py` 收录约 60 个常用名，其余请用代码搜索。
- **无登录与权限**：仅供本机单用户使用，默认只监听 `127.0.0.1`。要放到公网必须先加认证与反代。
- **不含下单能力**：只读 + 模拟，不接任何券商交易接口；新增/修改持仓只改本系统账本，不会同步到券商。
- **剔除是逻辑剔除**：`reject` 行仍在库里，只是不参与合计。要物理删除或恢复，改 `quality` 字段即可。
- **删除持仓不留痕**：目前是硬删；需要可追溯就改成写 `status='closed'`（还没改）。
- **新增持仓不扣现金**：权益会立刻抬高，现金不变，杠杆因此下降；要如实反映买入，先 `POST /api/cash` 记一笔现金支出。

## 券商资金明细（富途）与交易关键指标

`app/statement.py` 把富途「资金明细」CSV（`交易类型/代码/名称/金额/余额/币种/创建时间`，UTF-8 BOM、全字段带引号）逐行入库到 `cash_flows`，并用最后一条余额改写该账户现金——**现金以券商流水为准，不再手抄**。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/statement/import` | `{path, account}` 导入 CSV；幂等（id = sha1 前 16 位），并刷新现金余额 |
| GET | `/api/statement` | 流水汇总：分桶（成交/股息/利息/基金/出入金/迁移）+ 月度/年度/逐标的 |
| GET | `/api/statement/rows?limit=&offset=&type=&symbol=` | 流水明细倒序分页 |
| GET | `/api/metrics` | 关键指标（总体 + 三账户）+ 4 条对账 + 资金去向 |

口径约定：

- **净外部投入** = 银行存入 + 银行取出（负数）+ 资产迁移/换汇净额。恒等式 `net_external + net_result = 末笔余额` 在 `statement.summary()` 里成立（2026-11-06：49,996.22 − 21,188.02 = 28,808.20，差 1 分是四舍五入）。
- **富途"已实现"用 232 条平仓事件（FIFO）**，不是券商现金净额。现金净额 −21,188.02 含费用、利息、股息与仍持仓的浮盈变动，两者并列显示、不互相替代。
- **POEMS 的已实现**沿用 ST 对账口径 6,662.84；逐笔明细合计 8,122.3 作为附注同时显示。
- **平均回报**有两个：单笔口径（每笔 `pl_pct / 持仓月数` 的均值，再 ×12 年化）与资金加权口径（已实现 / 净外部投入 / 年数，仅富途可算）。
- **持仓快照滞后**：台账持仓仍是 2026-09-24 18:04；此后 SQQQ/GLD 的成交（净卖出 36,140.48）只体现在现金里，所以组合页显示「台账权益 → 校正权益」，差额按成交金额估算，不是按数量重建。
